D. RETRY AND HUMAN-STATUS BOUNDARY
---------------------------------

Task starts
   |
   v
Attempt 1 --fails--> retry 1 --fails--> retry 2 --fails
                                                  |
                                                  v
                                      record all three attempts
                                      status = HUMAN_INSPECTION_REQUIRED
                                                  |
                                                  v
                                      automatic resume may rerun task
                                      no approval gate

LLM returns INSUFFICIENT_EVIDENCE
   |
   v
Keep deterministic verdict
   |
   v
Report row gets HUMAN_APPROVAL_REQUIRED audit column
   |
   v
Final report still generates

Human approval is visible, but it does not stop the execution or report flow.


E. RESPONSIBILITY SPLIT
----------------------

AGENTS
- coordinate;
- clarify;
- select tasks;
- enforce prerequisites;
- interpret structured evidence;
- prepare reviews and summaries.

PYTHON SCRIPTS
- parse and validate data;
- load databases;
- migrate snapshots;
- apply deterministic rules;
- validate LLM JSON;
- create final reports;
- reconcile counts and schema.

RULES / CONFIG
- define keys, fields, mappings, filters, KD priority, LLM scope, and report
  requirements without embedding secrets or production assumptions.

LLM
- second-pass analysis only for selected unresolved rows;
- no direct database mutation;
- no source-system access outside the supplied evidence package.

HUMAN REVIEW
- records review decisions and audit identity when supplied;
- has highest business-decision precedence;
- does not block the automated pipeline or final report in this project.
