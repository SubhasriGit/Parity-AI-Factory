CPP PM000003 STANDALONE PROJECT - DEMO RUNBOOK
============================================================

DEMO GOAL
---------
Show one complete, evidence-driven parity run from confirmed inputs to a final
report, while making the separation between agents, deterministic scripts, LLM
analysis, and human review obvious.

Recommended demo duration: 20-30 minutes.

------------------
1. Open this folder in VS Code.

Expected: 42 CPP tests pass; database valid; 250 mismatch, 250 verdict, and 250
workbook rows reconcile.

DEMO SECTION 5 - DETERMINISTIC ANALYSIS
---------------------------------------
Show docs/KD_RULES.md and scripts/classify_kd.py.

Explain the ordered rule engine:
- KD-7, KD-4, KD-3, KD-1, KD-5, KD-9, KD-6, KD-10, RAW_PARITY,
  RAW_MISMATCH_SAME_DAY, KD-2, KD-8, fallback.
- First match wins.
- Missing evidence is recorded separately; it does not silently downgrade a
  matched expected pattern.
- KD-2, KD-8, KD-9, and KD-10 remain EXPECTED when their pattern matches.
- A row with no matching KD remains POTENTIAL_ISSUE.

Expected synthetic classification distribution:
- EXPECTED: 200 (80%)
- POTENTIAL_ISSUE: 50 (20%)
- IMS_DATA_ISSUE: 0

DEMO SECTION 6 - LLM BOUNDARY
-----------------------------
Show output/llm_candidates.json and output/llm_findings.json.

LLM entry condition:
- candidate classification is POTENTIAL_ISSUE or IMS_DATA_ISSUE;
- this run sends 50 unresolved candidates.

LLM responsibilities:
- review the controlled evidence package;
- return structured JSON;
- propose supported classification, KD, confidence, hypothesis, evidence,
  missing evidence, and confirmation steps.

LLM exclusions:
- no schema creation;
- no direct database update;
- no CSV parsing;
- no IMS day-map inference;
- no hidden external source access;
- no override of EXPECTED rows;
- no final report decision by itself.

The bridge
  scripts/llm_bridge.py export
  scripts/llm_bridge.py import
validates the exchange.

INSUFFICIENT_EVIDENCE
- preserve deterministic classification;
- mark HUMAN_APPROVAL_REQUIRED in report audit columns;
- do not stop execution, resume, or final report generation;
- allow optional human review fields later.

DEMO SECTION 8 - RETRY AND AUTOMATIC RESUME
-------------------------------------------
Show scripts/run_pipeline.py and config/pipeline.yaml.

Default behavior:
- initial attempt;
- retry 1;
- retry 2;
- maximum three total attempts.

After all attempts fail:
- status/evidence includes HUMAN_INSPECTION_REQUIRED;
- attempt count, command, exit code, stdout, and stderr are retained;
- automatic resume continues and reruns the failed task;
- the marker is an inspection recommendation, not an approval requirement.
